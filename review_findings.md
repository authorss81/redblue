[MAJOR] src/interpreter.rs:721 — `observe_bindings` copies only `locals` and `globals` to the scratch VM, but not `qualified_members`, `modules`, `module_aliases`, `declared_modules`, or `objects`. This breaks module member calls (e.g., `files.write()`, `json.parse()`) in `.watch` expressions because `Vm::call_method` checks `qualified_members` to resolve `receiver.method` to the qualified builtin name. Without it, `files.write(...)` fails with "'files' has no method 'write'" instead of reaching the effectful-builtin refusal. The test `edge_a_watch_that_would_change_the_world_is_refused_and_writes_nothing` uses `files.write` without `import files`, so it likely fails for the wrong reason (missing method vs. refused effect) — the assertion checks for "files_write" in the refusal text, which would not appear in the actual error. Fix: extend `observe_bindings` to also copy `qualified_members` (and ideally `modules`, `module_aliases`, `declared_modules`, `objects`) from the observed VM.

[MAJOR] src/interpreter.rs:721 — The scratch VM's `steps` counter (step budget) is never reset between watch evaluations. `observe_bindings` resets `statement_depth` and drains output but leaves `steps`, `call_depth`, `loop_depth`, `loop_control`, and `assertions_failed` accumulating. With many watches or complex watch expressions (e.g., loops), the shared scratch VM can hit the step limit (default 32M) and cause subsequent watch evaluations to fail with a step-limit error. Fix: reset `steps = 0` (and other per-run counters) in `observe_bindings`, or create a fresh scratch VM per evaluation.

[MINOR] src/repl/debug_repl.rs:606 — TOCTOU in `read_argument`: between `read_source(argument)` failing and `std::fs::metadata(argument).is_ok()` check, the filesystem state can change (file created/deleted). If a file is created in this window, a previously-missing `.rb` file is reported as "cannot read" with a stale error; if deleted, a directory may be misclassified as code. Low practical risk for a REPL but a correctness gap. Fix: decide file-vs-code from the single `read_source` result; only fall back to metadata for the `.rb`-suffix rule.

A user can register unlimited watches, each evaluated at every statement boundary, causing O(watches × statements) work with no bound. If `observe` or `evaluate_watches` panics (e.g., due to a bug), the panic propagates out of `Vm::debug_before`, crashing the program being debugged instead of reporting a watch failure. Fix: wrap the hook body in `std::panic::catch_unwind` and report the panic as a watch error.
